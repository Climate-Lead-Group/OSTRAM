# inputs — authoritative model and scenario inputs

Hand-maintained inputs read by pipeline stages A1 to B2. Nothing under `inputs/` is generated
at runtime: every stage copies or materializes what it needs under the selected workspace
(`docs/lineage.md`, "Path ownership"). Code reaches these folders only through
`ostram.paths.ProjectPaths` (`osemosys_inputs`, `preparation_inputs`, `preparation_templates`,
`secondary_technology_inputs`, `scenario_inputs`, `execution_inputs`); an activated profile may
redirect any of those roles (`docs/lineage.md`, `examples/unescap/README.md`).

## Sub-folders

| Sub-folder | Contents | Generated by | Edit by hand |
|---|---|---|---|
| `osemosys_global/` | 64 CSVs: the OSeMOSYS set files (`TECHNOLOGY.csv`, `FUEL.csv`, `EMISSION.csv`, `STORAGE.csv`, ...) and one parameter file per OSeMOSYS parameter, in the raw form described in `docs/data-reference.md` | hand-maintained; read by A1 (`docs/pipeline.md`, "Prepare the base model") | Yes, with approval |
| `preparation/` | `centerpoints.csv` (country centre points used by country template generation, `ostram/pipeline/preparation/country_templates.py`); `secondary_technologies/` (5 workbooks: generation and installed capacity by source, technology shares, PET/OIL split, `Tech_Country_Matrix.xlsx`); `workbook_templates/` (6 templates: `A-O_AR_Model_Base_Year`, `A-O_AR_Projections`, `A-O_Demand`, `A-O_Parametrization`, `A-Xtra_Emissions`, `A-Xtra_Storage`) | hand-maintained; read by A1/A2 (`ostram/pipeline/preparation/base_inputs.py`) | Yes, with approval |
| `scenarios/` | `OSTRAM_Scenario_Inputs.xlsx` (scenario authority; carries its own README sheet, Source/Notes/References cells and cell notes) and `OSTRAM_Timeslice_Inputs.xlsx` (timeslice authority) | hand-maintained; read by A3 (`docs/pipeline.md`, "Build selected scenarios") | Yes, with approval |
| `execution/` | `firm_capacity_fallbacks_by_cr.xlsx`, the workbook behind the reserve-margin xlsx repair (`reserve_margin_xlsx_workbook` in `config/execution/Config_MOMF_T1_AB.yaml`) | hand-maintained; read by B2 (`ostram/pipeline/execution/orchestrator.py`) | Yes, with approval |

The workbooks were not opened for this README. They are described from `README.md`,
`docs/pipeline.md`, `docs/configuration.md`, `docs/data-reference.md` and `git log`.

## How to run

Nothing runs from this folder. `python -m ostram inspect-resources` reports the resolved
locations without creating a workspace. The stages that consume these inputs are run with
`python -m ostram run ...` (see `AGENTS.md`, "Canonical commands").

## Gotchas

- Any write under `inputs/` requires explicit approval (`AGENTS.md`). The pipeline never writes
  here; generated copies belong under `<workspace>/`.
- `Tech_Country_Matrix.xlsx` is both an input and a product: A1 reads the tracked copy
  (`ostram/pipeline/preparation/base_inputs.py`), and `docs/configuration.md` describes the
  generator (`ostram/pipeline/preparation/tech_country_matrix.py`). Regenerating it is a write
  under `inputs/`.
- Raw `osemosys_global/` PWR codes still carry the `00`/`01` duplicate suffix that A1 removes
  according to `pwr_cleanup_mode`; storage codes keep their `01` suffix in the compiled model
  (`docs/data-reference.md`, "Technology Codes").
- `osemosys_global/EMISSION.csv` lists `CO2<ISO3>` codes for many countries; only the six active
  countries are populated (`docs/data-reference.md`, "Emission Codes").
- The provenance notes added to the scenario workbook in September 2026 are documentation, not an
  input authority; the annual values remain the operational inputs (`README.md`).
