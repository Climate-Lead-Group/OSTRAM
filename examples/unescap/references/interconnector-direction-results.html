How to reproduce this comparison

The interconnector direction is controlled by a single YAML file that runs between the A3 and B1 pipeline stages.

Step 0 — Prepare the profile once (the profile ships inputs, not a built model):

python -m ostram example prepare unescap

Step 1 — Edit the direction authority in the profile:

examples/unescap/config/scenarios/B_Optimised_VRE/set_interconnector_direction.yaml

Set the direction for the interconnector technology:

directions:
  TRNBGDXXINDEA: forward      # or reverse, or bidirectional

Two ready-made variants sit next to it — set_interconnector_direction_EXAMPLE_forward.yaml and set_interconnector_direction_EXAMPLE_reverse.yaml. Copy one over set_interconnector_direction.yaml instead of editing by hand.

Step 2 — Run the scenario. One command carries the whole chain; the direction rule is applied between the scenario and compilation stages:

python -m ostram --profile unescap run --scenario B_Optimised_VRE

Step 3 — Record a labelled snapshot after the run. Every run replaces the combined results, so without a capture the previous direction's numbers are gone:

python -m ostram example report unescap --capture forward

Then change the direction in the YAML and repeat steps 2–3 once per direction, capturing under reverse and bidirectional.

Step 4 — With the three snapshots on disk, generate the side-by-side comparison:

python -m ostram example report unescap --compare forward,reverse,bidirectional
  • forward keeps only the mode whose input fuel matches the source region (BGDXX)
  • reverse keeps only the mode whose input fuel matches the destination region (INDEA)
  • bidirectional is the default — both modes stay active
