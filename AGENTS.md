## Purpose

This file is the entry point for AI coding agents (Claude Code, Codex, Cursor, …) and for
people new to the repo. It states how the repo is documented and how an agent must work in it.
`CLAUDE.md` only contains `@AGENTS.md`; there is no separate Claude-specific configuration.

## How to navigate

1. Read the **Repo-specific block** below first (what the repo is, layout, canonical commands).
2. **Before editing anything inside a folder, read its `README.md`.** That is the folder's own
   README or, for a folder mapped in `COVERED_BY_PARENT` of the checker, its parent's (see
   "Folder README convention"). Either way it has a `## Scripts` table (what each script does,
   reads, writes, how to run).
3. **Before running a script, read its module docstring** (`Inputs:` / `Outputs:` / `Usage:`).
4. Only then open the code. Public functions with non-obvious logic carry a docstring; private
   helpers usually do not, read their body.

## Docstring convention

English, Google style, `"""triple double quotes"""`, summary line in the imperative, one sentence.
File names, sheet names, scenario codes and model parameter names are written verbatim, never
translated.

**Module docstring — required in every `.py`** (except `__init__.py`). Sections, in this order,
omitting the ones that do not apply:

```python
"""One-line summary of what this script/module does.

Optional context (2-6 lines): where it sits in the chain, key assumptions.

Inputs:
    path/to/file.xlsx (sheet "Name")        # what it reads
Outputs:
    path/to/output/                          # what it writes
Usage:
    python path/to/script.py --flag VALUE    # required for executable scripts
Notes:
    - Must run after X and before Y.
Authors:
    2021 Original Author; 2025 Org, Maintainer   # keep existing authorship here, never invent it
"""
```

The first non-empty line must be the summary. A docstring that only contains an authorship header
(`Created on … @author …`) counts as missing.

**Function / class docstring — required when the object is public (no leading `_`) and:**

- the module is a **library** (listed in `LIBRARY_DIRS` of the checker, or imported by two or more
  other modules): then **every** public function, class and method needs one; or
- the body is longer than 30 lines; or
- it writes to disk, mutates an argument or global state; or
- it encodes domain logic that is not obvious from the code (units, cut-off years, preconditions
  on the data, position inside a patch chain).

Exempt: private helpers (`_x`), nested functions, `main()` of figure scripts (documented in the
folder README), one-screen wrappers whose name says it all.

```python
def apply_floor(df: pd.DataFrame, year_from: int, factor: float = 1.01) -> pd.DataFrame:
    """Raise the cap to floor × factor wherever the floor exceeds the cap.

    Args:
        df: "Secondary Techs" sheet as loaded by load_sheet(); modified in place.
        year_from: first year (inclusive) to patch.
        factor: multiplier applied to the floor.

    Returns:
        The same DataFrame, for chaining.

    Raises:
        ValueError: if a cap cell is EMPTY.

    Side effects:
        Mutates df in place. Does not write to disk.
    """
```

`Returns:` is omitted for `None`; `Raises:` and `Side effects:` only when they apply. A one-line
docstring is fine when the typed signature already explains the arguments.

## Folder README convention

Every folder under the code roots that directly contains `.py` files has a `README.md` in English
with these sections, in this order:

```markdown
# path/to/folder — one-line purpose

Context paragraph (2-5 lines). Link to the spec or doc page if one exists.

## Scripts

| Script | What it does | Reads | Writes | Run |
|---|---|---|---|---|
| `x.py` | … | `inputs/...` | `outputs/...` | `python path/to/x.py [--flag]` |

## How to run

Canonical commands from the repo root, naming the environment to activate.

## Order / dependencies    <!-- only if the scripts form a chain -->

## Gotchas                  <!-- "None known." is acceptable -->
```

The `## Scripts` table lists **every** `.py` in the folder. Historical one-shot scripts that must
not be re-run say so in *What it does*. A small sub-folder may be documented by its parent's README
instead (mapped in `COVERED_BY_PARENT` of the checker); its scripts then appear in the parent's table
with their relative path (`sub/x.py`). Data folders (inputs/outputs roots) have one README with a
table of their first-level sub-folders: contents, generated by, edit by hand or not.

## Working rules for agents

- Do not edit generated/output folders by hand; regenerate them with the documented command.
- Do not run expensive steps or steps that modify tracked data without explicit approval from the
  user **in the current task**. The repo-specific block lists which steps those are.
- Resolve paths through the repo's path module, never hard-code `inputs/…` or `outputs/…`.
- Documentation changes (docstrings, READMEs) never change logic. Prove it with
  `python tests/check_docs.py --compare-ast <base-ref>` before committing.
- A commit that changes logic must (a) run the safe tests listed in the repo-specific block,
  (b) add or extend a test when it touches a library module or a function with domain logic, and
  (c) name the tests that were run in the commit body.
- Preserve line endings: check `git ls-files --eol <file>` before rewriting a file; CRLF files
  stay CRLF.
- Commit messages: conventional prefix (`feat`, `fix`, `docs`, `chore`), imperative subject,
  no AI co-authorship trailer.
- If something looks wrong but is out of scope, write it under `## Gotchas` of the folder README
  or report it; do not fix it silently.

## Checks before committing

```bash
python tests/check_docs.py            # READMEs + docstrings; must exit 0
python tests/check_docs.py --compare-ast <base-ref>   # for docstring-only commits
# plus the repo's own tests (see repo-specific block); mandatory for commits that change logic
```

The checker only sees files known to git (`git ls-files`). Run it **after `git add`**, or a new
`.py` is silently skipped and never reported as missing a docstring or a README entry.

## Bootstrapping this convention in a new repo

1. Copy `AGENTS.md`, `CLAUDE.md` and `tests/check_docs.py` to the new repo.
2. Delete everything below the `REPO-SPECIFIC BLOCK` marker and rewrite each section under that
   marker for the new repo (repo name and purpose, layout, folder map, canonical commands, actions
   that require approval, known gotchas), keeping the section headings.
3. Edit the `CONFIG` block at the top of `check_docs.py`: `CODE_ROOTS`, `README_ROOTS`,
   `COVERED_BY_PARENT`, `LIBRARY_DIRS`, `EXEMPT_FILES`, `EXEMPT_FUNCS`, `FIG_GLOB`,
   `MIN_BODY_LINES`.
4. Run `python tests/check_docs.py --selftest` (must pass unchanged), then
   `python tests/check_docs.py --summary` for coverage counts per folder, and the plain
   `python tests/check_docs.py` (no flags) for the actual to-do list of missing items.
5. Write the missing folder READMEs first, then module docstrings, then function docstrings,
   folder by folder, committing per folder with `--compare-ast` green.
6. Confirm `CLAUDE.md` contains exactly `@AGENTS.md`.

## What this repo is

OSTRAM prepares, transforms, compiles and executes OSeMOSYS scenarios for South Asia (Bangladesh,
Bhutan, India as five regions, Nepal, Sri Lanka and the Maldives; see
`config/preparation/Config_country_codes.yaml`). It is an installable Python package driven by
`python -m ostram`, with a DVC pipeline (`dvc.yaml`: stages `preprocess` and `executing`) over
the same package commands. The stages are A1 (prepare the base model), A2 (add the transmission
network), A3 (build scenarios), B1 (compile model inputs) and B2 (run the model and collect
results); they are pipeline stages, not scenario names. The registry
(`ostram/pipeline/scenarios/registry.py`, maintained in `config/profiles/full.yaml`) declares four
roots (`BAU`, `A_Calibrated_BAU`, `B_Optimised_VRE`, `C_Target_VRE`) and 17 accepted decision
scenarios: `A_Calibrated_BAU`, `A_Calibrated_BAU_Clipped`, `B_Optimised_VRE`, `B_Opt_Clipped`,
`B_Opt_DirBidir`, `B_Opt_DirContractual`, `B_Opt_IndiaCosts`, `B_Opt_IndiaCostsFuel`,
`B_Opt_SolarCapex130`, `B_Opt_SolarCapexHi`, `B_Opt_SolarCapexSpike`, `B_Opt_TradeCap15`,
`B_Opt_TxCap150`, `C_Target_VRE`, `C_Target_VRE_Clipped`, `A_Calibrated_BAU_Clipped_TxFreeze2026`,
`B_Opt_Clipped_GrossImportCap15`. `BAU` is a support scenario, distinct from `A_Calibrated_BAU`
and not one of the 17. User documentation lives in `docs/` (Sphinx): `docs/pipeline.md`,
`docs/installation.md`, `docs/configuration.md`, `docs/regression.md`, `docs/lineage.md`.

## Layout

| Folder | Role | Edit by hand? |
|---|---|---|
| `ostram/` | The package: CLI (`__main__.py`), path resolution (`paths.py`), profiles, terminal, `pipeline/` (preparation, scenarios, compilation, execution), `reporting/`, `validation/`, and read-only package resources under `ostram/resources/` | Yes |
| `inputs/` | Authoritative model and scenario inputs (`osemosys_global/`, `preparation/`, `scenarios/`, `execution/`) | Only with approval (see below) |
| `config/` | Preparation, scenario, compilation, execution and profile configuration | Yes, except `config/execution/*.yaml` (approval) |
| `model/` | Maintained OSeMOSYS model source (`osemosys_fast_preprocessed.txt`) | Only with approval |
| `workspace/` | Gitignored mutable runtime state (preparation, scenarios, compilation, execution, logs), created lazily | **No** (generated) |
| `tests/` | Solver-free regression (`regression/`) and validation (`validation/`) suites, plus `tests/check_docs.py` | Yes |
| `docs/` | Sphinx site, with `docs/reference/` and `docs/acceptance/` sub-folders | Yes, but out of scope for docstring work |
| `timeslice_module/` | Timeslice workbook generator kept for training (`scripts/`, `inputs/`, `outputs/`, `docs/`) | Yes |
| `examples/` | The `unescap/` training profile (inputs, config, exercises, its own README) | Yes |

`ostram/paths.py` is the path module. `resolve_paths()` / `ProjectPaths.resolve()` pick the project
root and the mutable workspace with precedence CLI (`--project-root`, `--workspace`) > environment
(`OSTRAM_PROJECT_ROOT`, `OSTRAM_WORKSPACE`) > the editable checkout that contains the package, with
`<project-root>/workspace` as the default workspace. The caller's current directory is never a
resource root. Every stage reads inputs through `ProjectPaths` properties and writes only under the
selected workspace.

## Canonical commands

Run from the repo root inside the `OSTRAM-env` Conda environment, installed in editable mode.

```bash
conda env create -f environment.yaml
conda activate OSTRAM-env
python -m pip install -e .

python -m ostram --help
python -m ostram inspect-resources                                        # read-only, creates no workspace
python -m ostram run --skip-pull --compile-only --scenarios A_Calibrated_BAU   # solver-free boundary
python -m ostram transform --scenario A_Calibrated_BAU                    # A3 for one root scenario
python -m ostram compile-inputs --scenarios "A_Calibrated_BAU,B_Optimised_VRE" # B1 only
python -m ostram run --skip-pull --scenarios A_Calibrated_BAU --verbose   # SOLVER (hours) <- approval required

python tests/check_docs.py                        # documentation checker
python tests/check_docs.py --compare-ast <base-ref>   # docstring-only commits
```

Tests, as collected on 2026-09-29 with Python 3.12.3, pandas 3.0.6 and pytest 7.4.4:

```bash
PYTHONPATH=tests python -m pytest tests -q        # PowerShell: $env:PYTHONPATH="tests"; python -m pytest tests -q
# result: 349 passed, 16 failed, 3 errors in 8m40s (failures listed under "Known gotchas")
python -B -m unittest discover -s tests -p "test_*.py"   # the README's own form of the same suite
```

The 349 passing tests are the mandatory set for commits that change logic. The tests use
`unittest`; the `tests/validation/test_scenarios_lite.py` functions return tuples, which pytest
reports as `PytestReturnNotNoneWarning` (harmless today).

## Actions that require explicit approval

- `python -m ostram run` without `--compile-only` (solver, hours; writes under `workspace/`).
- `dvc pull` or `dvc repro`.
- Any write under `inputs/**` or `model/**`.
- Editing `config/execution/*.yaml` (`Config_MOMF_T1_AB.yaml` selects the solver and the patch
  chain for every run).
- Anything that regenerates `A2_Output_Params`, `Executables` or the combined
  `Inputs` / `Outputs` / `Combined_Inputs_Outputs` CSVs.

## Known gotchas

- **`C_Target_VRE` needs a solved `A_Calibrated_BAU` result.** `set_vre_targets.py` reads it from
  `OSTRAM_A_CALIBRATED_BAU_RESULT` or `bau_results_path` (`ostram/pipeline/scenarios/rules/set_vre_targets.py`
  lines 143-145); the registry resolves the declared dependency to
  `<execution-workspace>/Executables/A_Calibrated_BAU_0` unless overridden (`registry.py`
  `result_dependencies`, `config/profiles/full.yaml` `default_path`), and A3 accepts
  `--a-result-seed` (`materializer.py`). Solve A first, then the other 16 with `--a-result-seed`
  (`docs/pipeline.md`, "Accepted 17-scenario portfolio"). Omitting `--scenarios` selects support
  `BAU` and `C` without solving A first.
- **`storage_delay_active` silently wins over `strip_storage_active`.**
  `apply_configuration_overrides` in `ostram/pipeline/execution/orchestrator.py` (line 101) forces
  strip to `False` with only a printed notice. The datafile suffix chain (`StorageDelayN5`,
  `NoStorage`, `OpenBCK`, ...) is built from the active flags (same file, lines 679-685), so the
  `_NoStorage` datafile is only selected when delay is off and strip is on.
- **`reuse_existing_sol: True` with an existing `.sol` skips the solve** (`orchestrator.py` lines
  1047-1060; `--compile-only` forces it to `False`, line 130). To know whether a solve happened,
  check the mtime of `<output_file>.cplex.log` (the CPLEX log path set at line 900).
- **Cost reconciliation only touches the frames in `RECONCILED_COST_FRAMES`**
  (`ostram/pipeline/execution/concatenate.py` line 40: `TotalDiscountedCost`,
  `DiscountedCostByTechnology`, `DiscountedOperationalCost`, `OperatingCost`,
  `AnnualVariableOperatingCost`). Frames absent from `Outputs/` are skipped with a `RuntimeWarning`
  and recorded as `missing_cost_frames` in the reconciliation JSON (lines 138-149); otoole is only
  lower-bounded (`otoole>=1.1.1` in `pyproject.toml`), so check the installed version when a
  frame is missing.
- **`TRNNLI*` technologies are unplanned new-line candidates, not real corridors**
  (`config/scenarios/technology_types.csv` category `TRANSMISSION_UNPLANNED_NR`;
  `Config_country_codes.yaml` section `TRNNLI`). Real interconnectors are category
  `INTERCONNECTORS` and follow `TRN<ORIGIN><DEST>` (for example `TRNINDSOLKAXX`).
- **Units.** Activity is in PJ and capacity in GW (`orchestrator.py` line 817;
  `CapacityToActivityUnit` is PJ/GW/year in `country_validation.py`); OLADE GWh inputs are
  converted with 1 GWh = 0.0036 PJ (`base_inputs.py` line 416). TWh = PJ / 3.6.
- **Runs from a git worktree can resolve to the main checkout.** Without `--project-root` or
  `OSTRAM_PROJECT_ROOT`, `ostram/paths.py` anchors the project on the package's own location
  (`_source_anchor`, line 94), and subprocess stages import the installed package. After any run
  from a worktree, check `git status` on the checkout that owns the editable install.
- **Line endings.** `.gitattributes` sets `* text=auto eol=lf` with deliberate exceptions:
  `config/scenarios/rules/pwr_min_2023_2026_pin.csv` is `eol=crlf` because it is byte-hash guarded
  (`tests/regression/test_apply_base_year_pin.py`), `*.bat`/`*.cmd` are CRLF, and `.dvc/.gitignore`
  is stored CRLF in the index. Do not normalise any of them.
- **`docs/regression.md` lists 15 governed scenarios; the registry has 17.**
  `A_Calibrated_BAU_Clipped_TxFreeze2026` and `B_Opt_Clipped_GrossImportCap15` are in
  `DECISION_SCENARIOS` (`registry.py`) but not in that page. The registry is the authority.
- **Some tests write inside the tree.** `test_b1_runner.py`, `test_run_orchestration.py` and
  `test_run_terminal.py` create temporary directories under `tests/regression/`
  (`tempfile.TemporaryDirectory(dir=TEST_ROOT)`, removed per test); `test_materialization_paths.py`
  creates them in the parent of the repo; `test_paths.py` creates
  `workspace/stage11-lazy-test/<Scenario With Space uuid>/` under the gitignored `workspace/` and
  never removes it, and needs `workspace/` to exist. The full suite is therefore not free of
  writes under `workspace/`; none of them touches tracked files.
- **Pre-existing test failures (2026-09-29, base environment above; not caused by documentation
  work).** File-lock `PermissionError` on temporary `.xlsx` (13 tests, including 3 teardown errors):

  `test_interconnector_taxonomy_path.py::InterconnectorTaxonomyPathTests::test_configured_rule_from_external_cwd_changes_only_direction_cells`,
  `test_materialization_paths.py::WorkbookRoundTripAndMaterializationTests` (3 tests),

  `test_restriction_prerequisites.py::RunStateHandoffTests::test_stage_4_5_reads_prerequisite_rows_from_exported_state`,
  `test_support_bau_transmission.py::SupportBAUTransmissionTests` (2 tests). pandas 3 requiring
