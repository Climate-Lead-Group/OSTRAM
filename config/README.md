# config — preparation, scenario, compilation, execution and profile configuration

Hand-maintained YAML, CSV and JSON that steer every pipeline stage. `docs/configuration.md`
documents the options of the four main YAML files; `docs/pipeline.md` explains which stage reads
each folder. Code reaches these files through `ostram.paths.ProjectPaths` (`config_root`,
`preparation_config`, `country_config`, `region_config`, `compilation_config`,
`execution_config`, `scenario_config_root`, `scenario_registry`, `interconnector_taxonomy`).

## Sub-folders

| Sub-folder / file | Contents | Generated by | Edit by hand |
|---|---|---|---|
| `preparation/` | `Config_country_codes.yaml` (countries, regions, technology codes, transmission tier parameters, `template_generation`); `Config_region_consolidation.yaml` (optional sub-region merge, currently disabled) | hand-maintained; read by A1/A2 | Yes |
| `scenarios/<Scenario>/` | Per-root rule YAML files consumed by `ostram/pipeline/scenarios/rules/` (`lid_rule.yaml`, `retirement_schedule.yaml`, `relax_interconnectors.yaml`, `bau_calibration.yaml` or `storage_floors.yaml`, `set_vre_targets.yaml`); 17 folders exist. `deprecate/` sub-folders and `*_v2` files are inert backups that no rule script loads (`docs/configuration.md`, "A3 Scenario Rule YAMLs") | hand-maintained; read by A3 | Yes |
| `scenarios/rules/` | Shared rule data: `internal_tx_residuals.csv` (`apply_internal_transmission.py`), `pwr_min_2023_2026_pin.csv` (`apply_base_year_pin.py`; byte-hash guarded, stored CRLF), `set_interconnector_direction.yaml` (`set_interconnector_direction.py`) | hand-maintained; read by A3 | Yes, except the pin CSV (see Gotchas) |
| `scenarios/sensitivities/` | `vre_ceilings.csv`, the provenance record behind the `vre_ceilings` block of `profiles/full.yaml` (`docs/reference/scenarios/vre_ceiling_provenance.md`); no module under `ostram/` reads it | hand-maintained | Yes |
| `scenarios/technology_types.csv` | Technology taxonomy (categories such as `INTERCONNECTORS`, `TRANSMISSION_UNPLANNED_NR`) used by the direction rule and manual fixes (`ProjectPaths.interconnector_taxonomy`) | hand-maintained; read by A3 | Yes |
| `profiles/` | `full.yaml` (the scenario registry `scenario_registry`, derived-scenario patches and `vre_ceilings` for the full model) and `registry.json` (profile registry: `full` and `unescap`; `ostram/profiles.py`) | hand-maintained; read by the CLI and A3 | Yes |
| `compilation/` | `Config_MOMF_T1_A.yaml`, the B1 compiler configuration (years, temporal structure, parameter lists) | hand-maintained; B1 copies it into `<workspace>/compilation/` and mutates only the copy (`docs/pipeline.md`) | Yes |
| `execution/` | `Config_MOMF_T1_AB.yaml`, the B2 configuration: solver, pipeline flags, datafile patch chain, CPLEX numerical-emphasis selection | hand-maintained; read by B2 and listed as a `dvc.yaml` dependency | Only with approval (`AGENTS.md`) |

## How to run

Nothing runs from this folder. `python -m ostram inspect-resources` prints the resolved registry
and execution-config locations. Changes take effect on the next `python -m ostram run`,
`transform` or `compile-inputs` invocation (`AGENTS.md`, "Canonical commands").

## Gotchas

- Identifiers in these files (technology, country and year codes) must exist in the model data;
  unknown codes fail during execution (`docs/configuration.md`, warning at the top).
- Scenario folders and registry entries are not one to one: `B_Opt_LinkFreeze`, `B_Opt_SolarHi10`,
  `B_Opt_TradeCap30` and `B_Opt_TradeCap50` have folders but are not decision scenarios, while
  `B_Opt_SolarCapex130`, `B_Opt_SolarCapexSpike`, `A_Calibrated_BAU_Clipped_TxFreeze2026` and
  `B_Opt_Clipped_GrossImportCap15` are decision scenarios defined only by patches in
  `profiles/full.yaml` (`ostram/pipeline/scenarios/registry.py`, `DECISION_SCENARIOS`).
- Rule YAML files under `scenarios/<derived scenario>/` (for example `B_Opt_DirBidir/lid_rule.yaml`)
  are not consumed by the materializer: derived scenarios are built by `apply_patches.py` from
  `profiles/full.yaml`, and only `set_interconnector_direction.yaml` is read, as the direction
  overlay. Rule YAML is read only for the roots run through `transform`. `BAU` has no folder, so
  only the lid rule (which tolerates a missing YAML) runs for it.
- `scenarios/rules/pwr_min_2023_2026_pin.csv` is byte-hash guarded and kept CRLF by
  `.gitattributes`; do not normalise it or change the accepted hash to bypass the guard
  (`README.md`, `tests/regression/test_apply_base_year_pin.py`).
- `bau_results_path` in `set_vre_targets.yaml` is resolved relative to the rule's staged working
  directory, not the repo root (`docs/configuration.md`, "A3 Scenario Rule YAMLs").
- `execution/Config_MOMF_T1_AB.yaml`: `storage_delay_active` silently forces
  `strip_storage_active` to `False` (`ostram/pipeline/execution/orchestrator.py`,
  `apply_configuration_overrides`).
