# model — maintained OSeMOSYS model source

The GMPL model text that B2 solves. It is a read-only model authority (`docs/lineage.md`,
"Path ownership"): B2 reads it through `ProjectPaths.maintained_model` and derives any patched
variant under the workspace, never in place.

## Contents

| File | Contents | Generated by | Edit by hand |
|---|---|---|---|
| `osemosys_fast_preprocessed.txt` | OSeMOSYS FAST model (Apache 2.0 header from the OSeMOSYS steering committee), preprocessed for `glpsol` matrix generation; a `dvc.yaml` dependency of the `executing` stage and the value of `osemosys_model` in `config/execution/Config_MOMF_T1_AB.yaml` | hand-maintained (last changed in the September 2026 cost release, `git log`) | Only with approval (`AGENTS.md`) |

The file was described from its header, `dvc.yaml`, `docs/pipeline.md` and `git log`; it was not
reviewed line by line for this README.

## How to run

Nothing runs from this folder. B2 (`python -m ostram run` without `--compile-only`) generates the
matrix from this model and the compiled scenario datafile (`docs/pipeline.md`, "Run the model and
collect results").

## Gotchas

- When `storage_delay_active` is true, B2 writes a patched model
  (`storage_delay_model_output`, default `osemosys_fast_preprocessed_storage_delay.txt`) and points
  `osemosys_model` at it for that run (`ostram/pipeline/execution/orchestrator.py`,
  `apply_configuration_overrides`); the maintained file is not modified.
- Any change here alters every scenario's LP. Reproductions compare LP hashes exactly
  (`docs/pipeline.md`, "Compare a reproduced portfolio"), so a model edit invalidates the accepted
  portfolio comparison.
