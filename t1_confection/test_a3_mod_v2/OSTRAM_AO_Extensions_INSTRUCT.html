The Tab 1 column reference

A walkthrough of every column in OSTRAM_AO_Extensions.xlsx → 1_Extensions_To_Add — what each cell means, who fills it, and what stage 3 will do with it.

§1The three buckets

Every column belongs to one of three buckets, distinguishable by the coloured rail on the left of each entry below.

Bucket A · Read-only
Script-filled context
Information about the missing code. Don't edit these — they're observation, not instruction.
Bucket B · Suggested defaults
Auto-suggested, editable
The script's best guess. Override only when you have a reason.
Bucket C · Your decisions
Decision columns
These drive stage 3. The values you enter determine what gets written into A-O.

§2Bucket B — Auto-suggested defaults

Suggested_Template_AO
Means
An existing A-O Parametrization code that the script believes is the right pattern to copy. Stage 3 clones this code's parameter rows when adding the new code.
Values
An A-O code (e.g. PWRNGSINDEA) or blank.
Blank means
No same-category code exists in A-O Parametrization → you must fill Override_Template_AO instead.
For PWRNGSBGDXX, the script wrote PWRNGSINDEA here because that code already exists in A-O and shares the same prefix+category (PWRNGS).
Suggested_Tech.Name_AO
Means
The Tech.Name attached to the suggested template, in A-O house style. Stage 3 will use a region-substituted version of this name when writing the new code.
Values
A Tech.Name string or blank.
Blank means
Either no template was suggested, or the template had no Tech.Name in A-O.
For PWRNGSBGDXX, this would be the Tech.Name from PWRNGSINDEA ("Natural Gas (Power generator) India, region EA"). Stage 3 substitutes the region to produce the Bangladesh version.
Add_To_Param · Add_To_AR_Base · Add_To_AR_Proj · Add_To_Demand
Means
The four propagation flags. Y = "add the new code to this workbook." N = "don't."
Values
Y, N, or blank.
Default
The script checks where Suggested_Template_AO currently lives across the four A-O workbooks and copies that footprint. So if PWRNGSINDEA is in Param + AR_Base + AR_Proj but not in Demand, the row gets Y/Y/Y/N.
Blank means
No template was suggested → script left these blank for you to decide manually.
When to edit
Only when you have a reason to deviate from the template's footprint (e.g., you decide a new code goes in AR_Base but not AR_Proj for a country-specific reason).
PWRNGSBGDXX → Y/Y/Y/N is correct as-is. You wouldn't touch these unless there's a special reason.

§3Bucket C — Your decision columns

Include
Means
The master on/off switch for this row. Stage 3 only processes rows where Include = Y.
Values
Y or blank.
Default
Y for the 5 PWRSHP codes (v17-driven, definite). Blank for everything else.
What you do
Leave Y for rows you've reviewed and want to keep. Set Y for any blank-default rows you decide to add. Leave blank to skip a row entirely (stage 3 ignores it).
After consulting Andrey, if you decide PWRGEOINDNO doesn't belong in A-O yet, leave Include blank and that row is skipped.
Override_Template_AO
Means
An A-O code you choose manually as the template, overriding whatever's in Suggested_Template_AO (or filling in when suggested is blank).
Values
An A-O code that exists in A-O Parametrization, or blank.
Blank means
Use whatever Suggested_Template_AO says.
Stage 3 logic
If Override_Template_AO is non-blank, stage 3 uses it instead of the suggested one.
When to edit
Always when Suggested_Template_AO is blank and you've decided what to use. Or when you disagree with the suggestion (rare — same-category match is usually right).
For PWRSHPINDEA, you'd type PWRHYDINDEA here. For PWRGEOINDNO, you might type PWRBIOINDNO — or whatever baseload analogue you choose with the team.
Override_Tech.Name_AO
Means
The Tech.Name string you want stage 3 to write for the new code, overriding the auto-generated name.
Values
Any string, or blank.
Blank means
Stage 3 generates a Tech.Name automatically by taking the template's name and substituting the region.
When to edit
When you want exact A-O house-style wording the auto-substitution wouldn't produce. Especially when the template's name pattern doesn't map cleanly — e.g., for PWRSHP using PWRHYD as template, the auto-generated name would say "Hydroelectric"; you'd want "Small Hydropower".
For PWRSHPINDEA with Override_Template_AO = PWRHYDINDEA, you'd type Small Hydropower (Power generator) India, region EA here so stage 3 writes that exact string.
Notes
Means
Free-text justification or context for the decisions you made on this row. Not used by stage 3 — purely for human readers (you, Andrey, Javier, future-you).
Values
Anything.
Default
[NEEDS_REVIEW: ...] for rows where the script left a template suggestion blank.
What you do
Replace [NEEDS_REVIEW] with the actual decision and reasoning when you settle the row. Or leave blank if no commentary needed.
"Override template = PWRHYDINDEA. Discussed with Andrey 2026-04-28 — small hydro inherits large hydro's parameters; tech.name swapped to A-O small-hydro convention."
