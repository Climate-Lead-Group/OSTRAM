The rules behind a result

A result is only as meaningful as the limits it was solved under. In OSTRAM those limits are not typed by hand into the model: rule scripts write them, in a fixed order, from settings files and workbook sheets. Step through the order for each root scenario below. Each card names the module, its settings and what it writes.

Why the order matters

Each rule reads what earlier rules wrote. The retirement rule shrinks existing capacity first, because the build-cap rule sizes caps from it. The interconnector rules run after the build-cap rule, which skips interconnectors. The base-year pin runs last, so reviewed historical values are the final values; a derived scenario applies it again after its edits. The full list of reasons is in the rules reference below.

Reading a cap in a solved run

Once a scenario is solved, compare what was built with the cap of that year. Built equal to the cap means the cap decided; built below it means cost decided. A cap of 9999 means no practical limit, and a cap of 0 allows nothing. The build caps page explains where each value comes from.
