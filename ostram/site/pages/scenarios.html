Scenarios

Every scenario of an application starts from the same calibrated data. Scenarios differ only in the rules that write their limits and in the edits applied on top, so each difference in a result can be traced to a stated assumption.

Three kinds of scenario

Support

BAU

Runs only the build-cap rule. It is not a decision scenario: it exists so that the calibrated root can inherit its limits.

Roots

A, B and C

A_Calibrated_BAU grows the fleet in proportion and is the calibration anchor. B_Optimised_VRE takes the looser of its own limits and A's, cell by cell, so it never costs more than A. C_Target_VRE turns renewable share targets into generation floors sized from a solved A.

Derived

Edits on a root

A copy of a root with the shared renewable ceilings and a list of edits applied, then the base-year pin again. Clipped, trade, direction, cost and freeze variants are all built this way.

How a derived scenario is built

  1. 1

    Copy the parent

    The root is built first, with its rules in their order (see the rules behind a result).

  2. 2

    Apply the shared ceilings

    Unless the scenario opts out, the solar and wind ceilings of the setup are written. "Clipped" in a name means a root plus these ceilings.

  3. 3

    Apply the edits

    The edits of scenario.yaml run in list order: set a value, scale it, cap imports, zero a family.

  4. 4

    Pin the base years again

    Reviewed base-year values are written again, so no edit can replace them.

  5. 5

    Log every change

    An edit log records each cell that changed, for checking.
